# save-conversations

Claude Codeとのやり取りは、セッションが終わると読み返す手段が乏しい。このスキルは、今の会話の内容を後から検索・参照できる形でリポジトリのローカルに書き出す。あくまで個人の作業ログであり、チームで共有するドキュメントではないため、Git管理には含めない前提で運用する。

## 出力仕様（固定条件）

- **保存先**: リポジトリ本体（メインのworktree）の `.claude/conversations/`
- **ファイル名**: `YYYY-MM-DD_HHMMSS_テーマ名.md`（日付・時刻は実行時点の実際の日時、テーマ名は会話の主題を表す短い日本語）
- **本文構成**:
  - `## まとめ` — 何を相談し、何を決め、何を作った/変えたかの要約（冒頭に使用モデル名を明記する）
  - `## 会話履歴` — `### User` / `### Claude` を交互に並べたやり取りの再現

## 手順

1. **保存先ディレクトリを確認・作成する**
   - 現在の作業ディレクトリがgitのworktree（メイン以外）かどうかを確認する。`git worktree list --porcelain` の出力で先頭の `worktree <path>` がメインworktreeの絶対パスなので、それが現在の作業ディレクトリと異なる場合は、そのメインworktreeのパス配下の `.claude/conversations/` を保存先にする（会話ログはセッション個人の作業ログであり、セッション終了時に削除されうる一時worktreeではなく、メインの作業コピーに集約して後から一箇所で読み返せるようにするため）。gitリポジトリでない、またはworktreeが1つしかない場合はそのまま現在の作業ディレクトリ配下の `.claude/conversations/` を使う。
   - 決定した保存先ディレクトリが存在しなければ作成する。ワークツリー分離ポリシーにより現在の作業ディレクトリ外への書き込みがEdit/Writeツールで拒否される場合は、ファイル作成・移動をBashツール（`mkdir`, `mv`等）で行う。
   - `.gitignore` への登録確認は毎回行わない（個人ログとしてGit管理対象外にする設定は初回セットアップ時点の話であり、以降のセッションで都度チェックする必要はない）。ユーザーから明示的に依頼された場合のみ確認・追記する。

2. **実行時点の日時を取得する**
   - `date +%Y-%m-%d_%H%M%S` などコマンドで実際の日時を取得する。会話の中で言及された日付やシステムリマインダーの日付表記を鵜呑みにせず、ファイル名には実行時点（ファイル書き込み直前）の日時を使う。時刻まで含めることで、同日に複数回保存しても自動的にファイル名が分かれる。

3. **テーマ名を決める**
   - 会話全体の主題を要約した短い日本語（10〜20文字程度が目安）にする。
   - ファイル名として安全になるよう、スペースや `/` `:` などパス上問題になる文字はアンダースコアなどに置き換える。
   - 明らかに主題が定まらない雑談的な会話であれば、無理に凝った名前をひねり出さず「雑談」「相談」のような素直な語でよい。

4. **同名ファイルの衝突を確認する**
   - ファイル名に秒単位の時刻まで含まれるため通常は衝突しないが、万一同名のファイルが既に存在する場合は無言で上書きせずユーザーに確認する（追記が目的なら別テーマ名にする、更新でよければ上書きするなど、意図を聞く）。

5. **使用モデル名を確認する**
   - システムプロンプトやシステムリマインダー中のモデル識別情報（例:「You are configured to run on the model `claude-sonnet-5`」）、または `/model` コマンドの実行結果などから、保存時点で実際に使用しているモデル名を取得する。マーケティング名ではなく実際のモデル識別子（例: `claude-sonnet-5`）を使う。
   - セッション中に `/model` などでモデルが切り替わっている場合は、その経緯も分かるように記録する（例: `claude-opus-5` → `claude-sonnet-5`（会話途中で `/model` により変更））。
   - モデル名が特定できない場合は無理に断定せず、不明である旨を正直に記載する。

6. **まとめを書く**
   - まとめの冒頭に「**使用モデル**: `<モデル名>`」の形で5で確認したモデル名を記載する。
   - 続けて、会話の目的、決定事項、成果物（作ったファイル・変更した設定など）を3〜6文程度で簡潔にまとめる。

7. **会話履歴を再構成する**
   - 今のセッションのコンテキストに残っているやり取りをもとに、`### User` と `### Claude` を時系列で交互に並べて書き出す。
   - これは生のログをそのまま複製するものではなく、コンテキストから再構成したものである点に注意する。非常に長いセッションでは、序盤の内容が要約によって圧縮されていて再現できない場合がある。その場合は正直にその旨を「まとめ」に一言添える（存在しない発言を捏造しない）。
   - ツール呼び出しの詳細まで逐一書き起こす必要はない。何をしたか（例:「〇〇ファイルを読んで内容を確認した」）が伝わる程度の粒度でよい。

8. **書き出す前に機密情報を伏せ字にする**
   - 会話中でユーザーがsudoパスワード・APIキー・トークン・接続文字列などの機密情報をそのまま入力していた場合、まとめ・会話履歴のどちらに書く場合も原文の値をそのまま書き写さず、`********(sudoパスワード)` のように「伏せ字＋何の情報かの注記」に置き換える。
   - これは事後に気づいて修正するのではなく、ファイルに書き込む前の時点で毎回徹底する。理由は、`.claude/conversations/` は`.gitignore`されてはいるものの、ローカルディスク上には平文で残り続けるため、後から見返す・誰かに共有する・バックアップに含まれるといった場面で機密情報がそのまま漏れるリスクがあるため。
   - 何が機密情報にあたるか迷う場合は、安全側に倒して伏せ字にする（本人がその情報の重要性を過小評価している可能性があるため）。

9. **ファイルを書き込み、保存先を報告する**
   - 1で決定した保存先の `.claude/conversations/YYYY-MM-DD_HHMMSS_テーマ名.md` に書き込んだら、その絶対パスをユーザーに伝える。worktree内から実行してメインworktree側に保存した場合は、その旨（メインworktree側に保存した）が伝わるようにする。

## このスキルの対象外

- 生のトランスクリプトをバイト単位で保存する機能ではない。あくまでClaudeがコンテキストから再構成した要約的なログである。
- 保存したログをGit管理に含めるかどうかの判断はしない。`.claude/conversations/` を追跡対象外にする `.gitignore` 設定は初回セットアップ時点のものとして扱い、このスキルの実行のたびに確認・変更する対象ではない。
