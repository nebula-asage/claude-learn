# git-commit: 手順2・手順5の詳細（エージェントが存在しない場合）

`.claude/agents/git-committer.md` が存在しない場合に限り、以下の手動手順を実行する。エージェントに委譲する場合はエージェント自身が同じ内容を実行するため、このファイルを読む必要はない。

## 手順2. 保護対象のブランチにいるなら、作業用ブランチを切る

`git branch --show-current` で現在のブランチ名を取得する。

- 出力が `main` または `master` の場合 → 保護対象。新しいブランチを切る。
- 出力が空（detached HEAD状態）の場合 → これも保護対象として扱う。detached HEADのままコミットすると、ブランチに紐付かず後で辿れなくなり実質的にmain/masterへ直接コミットするのと同じくらい危ういため。
- それ以外のブランチ名（すでに作業用ブランチにいる）→ 新しいブランチは切らず、そのままステップ3へ。

新しいブランチを切る場合の手順:

1. 差分の内容から、SKILL.md本文の「Conventional Commitsのtype早見表」を参考にtypeを1つ判定する。
2. 変更内容を要約した短い英単語スラッグ（小文字・ハイフン区切り、2〜4単語程度）を作る。例: `add-login-form`, `fix-null-pointer`。ブランチ名はツールやリモート間の互換性のため英数字とハイフンのみで構成し、日本語や記号は使わない。
3. ブランチ名を `<type>/<slug>` の形にする（例: `feat/add-login-form`）。
4. そのブランチ名がすでに存在する場合（`git branch --list <name>`で確認）、末尾に `-2`, `-3` のように連番を付けて衝突を避ける。
5. `git checkout -b <branch-name>` でブランチを作成する。

## 手順5. pushできるならpushする

コミットが完了したら、破壊的な操作をせずにpushを試みる。

- 新しくブランチを作った場合（手順2を通った場合）: `git push -u origin <branch-name>` でupstreamを設定しながらpushする。
- 元から作業用ブランチにいて新規ブランチを作らなかった場合: まず `git push` を試す。upstreamが未設定なら同様に `-u origin <branch-name>` を付けて試す。

push時に次のような状況になったら、force pushや `--force-with-lease` などで無理に押し通さず、状況をそのままユーザーに報告して判断を仰ぐ:

- リモート `origin` が設定されていない、またはネットワーク的に到達できない
- 認証エラーで拒否される
- リモート側が進んでいて（diverged）、単純pushでは拒否される
- ブランチ保護ルールなどで拒否される

pushが飛ばされた・失敗した場合でも、ローカルのコミット自体は完了しているので、それはそれとして成功と報告する。
