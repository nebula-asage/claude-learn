# template-drift-sync

このリポジトリでは、開発環境の構成をスキルの`templates/`配下にテンプレートとして持ち、それを各プロジェクトへコピーして使う。そのため、テンプレート側を改善しても既に配置済みのファイルは自動では追従せず、放置すると「スキルは直っているのに配置済みが古い」というドリフトが溜まる。このスキルは、その差分を検出して追従させるためのもの。

配置済みファイルには**プロジェクト固有の意図的な追記**が入っていることが多く、単純な上書きコピーは破壊的になる。差分を分類したうえで、テンプレート由来の変更だけを取り込むのがこのスキルの要点。

## 手順

1. **ドリフトを検出する**

   ```bash
   python3 .claude/skills/template-drift-sync/scripts/check_drift.py --only-suspect
   ```

   - `.claude/skills/*/templates/`配下の各テンプレートについて、git追跡ファイルから対応する配置先を探して差分を出す。
   - `--only-suspect`は「配置済みに行が増えただけ」の差分を隠し、テンプレート側の内容が配置済みに反映されていない疑いのあるものだけを表示する。まずはこれで全体像を掴む。
   - 全件見たい場合はフラグ無しで実行する。特定のスキル・配置先に絞る場合は`--skill <名前>`・`--path-filter <部分パス>`を使う。
   - 終了コードは 差分あり=1 / 差分なし=0。

2. **差分を3つに分類する（このスキルの中心）**

   検出された差分は、必ず以下のどれに当たるかを1件ずつ判断する。テンプレートを配置済みファイルへ機械的に上書きしてはいけない。

   - **(a) テンプレート更新の未反映** → 追従対象。テンプレート側が改善されたのに配置済みが古いままのもの。
   - **(b) プロジェクト固有の意図的な追記・改変** → そのまま維持する。例: devcontainerのDockerfileにNode/pnpmやuvの導入を足している、共通の`settings.json`に言語固有の設定を足している、テンプレートのコメントによる手引きを実際の実装で置き換えている。
   - **(c) プレースホルダ置換の結果** → 差分ではない。スクリプトは配置先パスから`__PROJECT_NAME__`等を推測して置換済みだが、推測できない箇所は差分として出る。

   判断に迷ったら、そのテンプレートファイルの変更履歴を見ると (a) か (b) かを切り分けやすい。

   ```bash
   git log --oneline -- .claude/skills/<skill>/templates/<file>
   git log --oneline -- <配置済みファイル>
   ```

   テンプレート側にだけ後から入ったコミットがあれば (a)、配置時から配置済み側にしか無い変更なら (b) の可能性が高い。

3. **(a) に該当する差分だけを反映する**
   - Edit ツールで該当箇所だけを書き換える。ファイル全体のコピーは、(b) の追記が無いと確認できた場合に限る。
   - 1つのファイルに (a) と (b) が混在するのが普通なので、(b) を巻き込んでいないか反映後に必ず差分を読み返す。

4. **反映結果を検証する**
   - 変更したファイルの種類に応じて、実際に動かして確認する。設定ファイルを直しただけで動作確認を省略しない。
     - Dockerfile / devcontainer.json: `docker build`が通ること。ロケール・タイムゾーン・sudo・bash補完など、そのテンプレートが保証している性質が壊れていないこと。
     - JSON・JSONC（`settings.json`・`extensions.json`・`devcontainer.json`）: コメントを除去してからパースが通ること。値に`//`を含む文字列が無いことを確認したうえで `sed 's|//.*||' <ファイル> | jq .` を使う。
     - 各プロジェクトの設定ファイル（`pyproject.toml`・`package.json`・`.golangci.yml`等）: そのプロジェクトのlint・テスト・ビルドを実行して通ること。
   - 検証で作った一時ファイル・一時Dockerイメージ・生成物は必ず削除する。

5. **再度検出して結果を確認する**
   - 手順1のコマンドを再実行し、(a) が解消され、(b) だけが残っていることを確認する。
   - (b) として残す判断をしたものは、報告時に「意図的に残した差分」として明示する。放置ではなく判断の結果であることが後から分かるようにする。

6. **報告する**
   - 追従したファイルと内容、意図的に残した差分、検証内容を報告する。
   - 差分が多く一度に対応しきれない場合は、残りを`.claude/TODO.md`に追記して次回に引き継ぐ。

## 検出スクリプトの仕組みと限界

`scripts/check_drift.py`は、テンプレートからの相対パスの**末尾一致**で配置先を探す（配置先ではディレクトリ名の先頭に`.`が付くことがあるため、各セグメントの先頭ドットを無視して比較する）。

```
templates/vscode/settings.json      -> projects/foo/.vscode/settings.json
templates/devcontainer.json         -> .devcontainer/devcontainer.json
templates/scripts/install-husky.mjs -> projects/foo/scripts/install-husky.mjs
```

この方式には以下の限界があるため、スクリプトの出力は「候補」として扱い、最終判断は必ず自分で行うこと。

- **同名テンプレートの取り違え**: 複数のスキルが同じファイル名のテンプレートを持つ場合（例: 複数のOS向けdevcontainerがどちらも`Dockerfile`を持つ）、名前だけでは由来を区別できない。対策として、テキストの類似度が`--min-similarity`（既定0.5）を下回るペアは無関係とみなして除外し、1つの配置先に複数マッチしたときは最も似ているテンプレートだけを採用する。全件見たい場合は`--all-matches`を付ける。
- **一般的すぎるファイル名**: `README.md`と`.gitignore`はテンプレート直下にある場合、無関係なファイルに大量マッチするため既定で照合対象外。必要なら`--include-ambiguous`を付ける。これらは差分が出やすいので、分類（特に(b)の判定）を丁寧に行うこと。
- **配置先が未検出**: テンプレートに対応する配置済みファイルが1つも見つからない場合がある（まだどこにも配置していない、あるいはファイル名が配置時に変わっている）。`--list-unmatched`で一覧できる。
- **git未追跡ファイルは対象外**: 配置先の探索に`git ls-files`を使っているため、コミットされていないファイルは検出されない。

## このスキルの対象外

- スキルの`templates/`自体を書き換える作業（機能追加・仕様変更）は対象外。このスキルはテンプレートを正として配置済みを追従させる方向のみを扱う。逆に、配置済みで得られた改善をテンプレートへ還元したい場合もこのスキルの範囲外。
- 新規プロジェクトの新規作成は対象外。既に配置済みのファイルがあることが前提。
- 未マージブランチや不要ディレクトリの整理といった、テンプレートと無関係なリポジトリの後片付けは対象外。
