# workspace-audit

モノレポは、プロジェクトが増えるほど「壊れているのに誰も気づいていない」状態が溜まりやすい。このスキルは、その種の問題を機械的に洗い出すための調査手順である。

**読み取りと検証のみを行い、ファイルの変更はしない。** 修正は洗い出した後、ユーザーの指示を受けて別途行う。調査だけで完結するため、この作業のために worktree を作る必要はない。

## 調査の委譲

この調査は全プロジェクトの lint・テスト・ビルドを実走させるため出力が巨大になる一方、必要なのは「実害の大きい順の問題リスト」だけである。

`.claude/agents/workspace-auditor.md` が存在する場合、`Agent` ツールで `subagent_type: "workspace-auditor"` を指定し、構成把握からドリフト調査・報告まで（手動手順でいう1〜7に相当する全て）を委譲する。特に調べたい観点があれば添えて渡す。返ってくるのは3段階に分類された問題リストなので、それをそのままユーザーに報告する。

エージェントが存在しない場合は、`.claude/skills/workspace-audit/references/manual-steps.md` に書かれた手順1〜7を自分で実行する（このファイルは委譲する場合には読む必要がない）。

## TODOとして残す

**これは委譲しない。** エージェントはファイルを変更しないため、その場で対応しない項目の `.claude/TODO.md` への追記は、報告後にユーザーの指示を受けてから常に自分で行う。

既存の記法に合わせ、**番号は着手順ではなく識別用の固定ID**として扱い、一度振ったIDは変えず再利用もしない（後から会話で参照するため）。新しい項目には `.claude/TODO.md` の「使用済みID」の続き番号を振る。完了した項目は削除せずチェック済みにし、何をどう直したかを追記したうえで `.claude/TODO-archive.md` へ移す（どちらも gitignore 対象で git に履歴が無いため、削除ではなく移動にする）。

## このスキルの対象外

- 洗い出した問題の修正は対象外。修正はユーザーの指示を受けてから、通常の実装作業として行う
- コードレビュー（ロジックの正しさ・バグの検出）は対象外。ここで見るのは構成・運用・設定の健全性
- 個々のプロジェクト内部の設計改善提案は対象外
