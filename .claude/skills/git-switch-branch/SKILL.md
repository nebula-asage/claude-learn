# git-switch-branch

「ブランチ切り替えて」とだけ言われたとき、どのブランチに切り替えたいかはユーザーの頭の中にしかない。ここで独断でどれかのブランチ(例えば最近使ったものやmain)を選んで切り替えてしまうと、ユーザーの意図と違う場所に連れて行くことになる。このスキルは、切り替え候補を集めてユーザーに選ばせることを徹底するためのものである。

## 全体の流れ

1. 現在の状態を確認する
2. 未コミットの変更があれば、続行方法をユーザーに確認する
3. 切り替え候補のブランチを集める
4. ブランチ名が指示で明示されていなければ、候補をユーザーに選ばせる
5. 選ばれたブランチに切り替える
6. 結果を報告する

以下、各ステップの詳細。

## 1. 現在の状態を確認する

`git branch --show-current` で現在のブランチ名を、`git status --porcelain` で作業ツリーに未コミットの変更があるかを確認する。

- `git branch --show-current` の出力が空なら detached HEAD 状態。この場合「現在のブランチ」は候補から除外する必要がない(除外対象が存在しない)ので、そのまま次に進む。

## 2. 未コミットの変更があれば、続行方法をユーザーに確認する

`git status --porcelain` に出力がある場合、そのまま切り替えるとコンフリクトで失敗する、または変更が切り替え先に持ち越されて意図が分かりにくくなる可能性がある。ここで止まり、AskUserQuestionで次の3択をユーザーに選ばせる:

- **コミットしてから切り替える**: このスキルはコミット処理自体は行わない。「先に変更をコミットしてください。コミットが完了したらブランチ切り替えを進めます」と伝えて、ここで一旦終了する。
- **変更を退避(stash)してから切り替える**: `git stash push -u -m "switch-branch-auto"` で退避してから3以降に進む。切り替え完了後の報告で、退避した変更が残っている旨と `git stash pop` で戻せる旨を必ず伝える。
- **このまま切り替えを試す**: 何もせず3以降に進む。変更内容が切り替え先ブランチと衝突しなければgitは変更を保持したまま切り替えられるので、これは失敗するとは限らない。5でcheckoutが失敗したら、そのままエラー内容をユーザーに報告する(強制上書きはしない)。

## 3. 切り替え候補のブランチを集める

ローカルブランチとリモート追跡ブランチの両方を候補にする。次のコマンドで、直近の更新順に取得する:

```bash
git for-each-ref --sort=-committerdate \
  --format='%(refname:short)|%(refname)' \
  refs/heads refs/remotes
```

このリストから、次のものを除外する:

- 現在のブランチ(1で取得した名前)と同じ `refs/heads/...` の行
- `origin/HEAD` のようなリモートのシンボリック参照(`refname:short` が `<remote>/HEAD` の形になっている行)
- リモート追跡ブランチのうち、同名のローカルブランチが存在するもの。ここでの「ローカルブランチ」は、現在のブランチを除外した後の候補リストではなく、`refs/heads` 側の全ローカルブランチ(現在のブランチを含む)を基準に判定する。例えばローカルに `feature-x` があるなら `origin/feature-x` は除く。現在のブランチが `main` で、リモートに `origin/main` がある場合も同様に除く(`origin/main` は既に候補から外れた `main` の同名リモートに過ぎず、切り替え候補としては無意味な上、後述の `git checkout --track` はローカルに同名ブランチが存在すると失敗する)

残った候補は、ローカルブランチなら短縮名そのもの、リモート専用ブランチなら `<remote>/<name>` の形になっている。

候補が0件なら、「他に切り替え可能なブランチが見つかりませんでした」とユーザーに伝えてここで終了する。

## 4. ブランチ名が指示で明示されていなければ、候補をユーザーに選ばせる

ユーザーの指示に既に具体的なブランチ名(「mainに切り替えて」など)が含まれている場合は、この手順を省略して5に進んでよい。

含まれていない場合は、AskUserQuestionで候補を提示する。AskUserQuestionは1問あたり最大4択までしか選べないため:

- 候補が4件以下なら全件を選択肢にする。
- 候補が5件以上なら、直近更新順の上位4件のみを選択肢にする。それ以外のブランチに切り替えたい場合は、AskUserQuestionが常に提供する「その他」から自由入力でブランチ名を指定できる旨を質問文に一言添える。

各選択肢のdescriptionには、ローカルかリモート専用か(リモート専用の場合は選ぶとローカルに追跡ブランチが新規作成される旨)を明記し、判断材料にしてもらう。

「その他」で自由入力されたブランチ名は、3で集めた候補リスト(除外前の全ブランチでもよい)に対して完全一致・部分一致で照合する。一致が見つからない、または複数候補に一致してあいまいな場合は、`git branch -a`相当の一覧を示すか、もう一度具体的な名前を尋ねる。

## 5. 選ばれたブランチに切り替える

選ばれた候補がローカルブランチ名の場合:

```bash
git checkout <branch-name>
```

選ばれた候補がリモート専用(`<remote>/<name>` の形)の場合、ローカルに同名の追跡ブランチを作りながら切り替える:

```bash
git checkout --track <remote>/<name>
```

(`origin/foo` のようにリモートのプレフィックス付きのまま `git checkout` してしまうと detached HEAD になるので、必ず `--track` 付きで実行する。)

checkoutが失敗した場合、原因を切り分けてそのままユーザーに報告する。特に次のケースはこのリポジトリでの運用上よく起こりうるので、無理に解消しようとせず状況を伝える:

- そのブランチが既に別のgit worktreeでチェックアウト済み(「already checked out at ...」のようなエラー)
- 2で「このまま切り替えを試す」を選んだ後、実際に変更が競合して失敗した

## 6. 結果を報告する

最後に、次を簡潔にまとめてユーザーに伝える:

- どのブランチからどのブランチに切り替えたか
- リモート専用ブランチから新しく追跡ブランチを作成した場合はその旨
- 2でstashした場合は、退避した変更が残っていることと `git stash pop` で戻せる旨

## このスキルの対象外

- まだ存在しないブランチ名を指定しての新規ブランチ作成(`git checkout -b`)。ユーザーが明示的に「新しいブランチを作って」と言った場合は別途対応する。
- コミット、マージ、ブランチの削除。
- 未コミットの変更を破棄しての強制切り替え(`git checkout --force`、`git reset --hard`等)。ユーザーが明示的に指示しない限り行わない。
